Which of 100 apps can become an agent toolkit?

An evidence-first research agent (Composio search + local LLM) researched auth, access, API surface, MCP and buildability. Every claim links to a fetched source; quotes are machine-checked against the page text. Source repo · apps.json · apps.csv · llms.txt

1. Headline patterns

  • oauth2 is the most common auth method (52 of 100 apps list it).
  • 31 apps are self-serve today; 55 via trial; 0 are gated; 14 are unclear.
  • Most common blocker among non-ready apps: partner approval (29 apps).
  • 60 apps are ready_now (easy wins); 33 need outreach.
  • Existing MCP found for 81 apps; 10 unverified.
  • Only 75 of 100 records have at least one machine-verified evidence quote; 53 are flagged for a human.

4. The agent

seed list → search (Composio TAVILY_SEARCH) → fetch docs/pricing/MCP pages
  → [JS page? Composio TAVILY_EXTRACT → Playwright] → LLM extracts to fixed schema
  → CODE checks each quote is verbatim in the page → verifier LLM re-reads cited page
  → needs 2 independent pages for auth + self-serve → rule checks (dead links, contradictions)
  → low confidence / conflict ⇒ needs_human
  • Composio used: CLI-executed TAVILY_SEARCH and TAVILY_EXTRACT tools (logged-in CLI, no key in repo).
  • LLM: local Ollama (llama3.2 for pass 1, qwen2.5-coder:7b for pass 2): small models on purpose-constrained by code checks.
  • Where a human was needed: see HUMAN_INTERVENTIONS.md; count: flagged records.
