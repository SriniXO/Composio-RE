Which of 100 apps can become an agent toolkit?

An evidence-first research agent (Composio search + local LLM) researched auth, access, API surface, MCP and buildability. Every claim links to a fetched source; quotes are machine-checked against the page text. Source repo · apps.json · apps.csv · llms.txt

1. Headline patterns

  • oauth2 is the most common auth method (62 of 100 apps list it).
  • 81 apps are self-serve today; 11 via trial; 4 are gated; 4 are unclear.
  • Most common blocker among non-ready apps: paid plan (14 apps).
  • 82 apps are ready_now (easy wins); 2 need outreach.
  • Existing MCP found for 93 apps; 2 unverified.
  • 100 of 100 records have at least one quote found verbatim on a fetched page (this shows a source exists, not that the answer is right); 53 are flagged for a human.
  • How far to trust this: on held-out apps the final agent scored 80% (a pure guesser: 41%). Reliable fields: auth_methods, api_surface. Barely better than guessing: self_serve, existing_mcp, buildability, so counts of easy wins, self-serve apps and existing MCPs are upper bounds, not facts.

2. Easy wins vs needs outreach

Read this matrix as an upper bound. "Easy wins" and "needs outreach" come from the self-serve and buildability fields, where the agent was only about as accurate as guessing "yes" (section 7). 4. The agent

seed list → search (Composio TAVILY_SEARCH) → fetch docs/pricing/MCP pages
  → [JS page? Composio TAVILY_EXTRACT → Playwright] → LLM extracts to fixed schema
  → CODE checks each quote is verbatim in the page → verifier LLM re-reads cited page
  → needs 2 independent pages for auth + self-serve → rule checks (dead links, contradictions)
  → low confidence / conflict ⇒ needs_human
  • Composio used: CLI-executed TAVILY_SEARCH and TAVILY_EXTRACT tools (logged-in CLI, no key in repo).
  • LLM: local Ollama (llama3.2 for pass 1, qwen2.5-coder:7b for pass 2): small models on purpose-constrained by code checks.
  • Where a human was needed: see HUMAN_INTERVENTIONS.md; count: flagged records.
